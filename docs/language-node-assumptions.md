# Входы и выходы: правила расширения конструктора

Аудит 15 октября 2026. Реестр типов: `node_defs/*.json`; генерировать каталоги только через `tools.node_dev generate`.

## Решение о выходном словаре

Добавлен отдельный `token_labels` («Выбор токена»), использующий оформление существующего Output Labels. Подписи получает от backend, вручную перечислять словарь не требуется. По умолчанию показывает пять кандидатов, оставшуюся вероятность и постраничный поиск по словарю (50 строк).

Переключатель режима в старом `classifier` экономил бы одну позицию палитры, но смешивал бы два разных контракта: ручные классы с сохранёнными `label_names` и автоматический словарь с token IDs. Смена режима меняла бы сериализацию, обучение, результат inference и смысл существующих связей. Отдельный тип сохраняет старые проекты и делает ограничения явными. Общие визуальные элементы переиспользуются. `token_labels` — просмотрщик, выбор следующего токена происходит один раз в backend.

## Центральные правила

- Роль `input` в реестре означает источник данных. Нельзя определять все источники сравнением с `InputNode`. `GraphRoles.is_input` используется для обхода, меню и выбора корня.
- Числовой runtime выбирает только `GraphRoles.is_numeric_input`. Текст не является массивом значений датчиков или изображением.
- Роль `language` означает новый языковой тип, `sequence_capable` — существующий Dense/Concat/Softmax, поддерживаемый адаптером. Реестр использует эти роли также при генерации совместимости документации.
- `is_input` в Graph остаётся механизмом владения контекстом, слияния графов и ограничения копирования. TextInput устанавливает этот флаг. TrainBegin также является корнем, но не источником модельных данных.
- `LanguageGraphAdapter.component` идёт только по связям данных. Порты конфигурации активации/датасета не превращаются в тензорные операции.
- Тип порта `layer1d` сам по себе недостаточен. Языковой адаптер разрешает только поддержанные операции и проверяет формы `T × D`, число источников, циклы, Concat и размер выходного словаря.
- Dense в языковом компоненте разрешает размер до 65536, обычный Dense сохраняет лимит 2048. Параллельные головы и две ветки Softmax требуют нескольких исходящих связей.
- Демо-сессии, трассы, распределения, выбранные позиции и координаты визуализации не являются конфигурацией модели. Не сохранять их в `cfg` и не создавать undo-действия при получении результата.
- Контроллер работает независимо от отсечения невидимых нодов: GraphManager отключает процессинг Graph вне экрана. Иначе отсоединённые ветки могут сохранять устаревший результат. При сбросе очищаются также захваченные ранее участники, а не только текущий компонент.
- Ответы backend проверяются по request ID и revision; просмотр внимания также проверяет session ID. При изменении графа старые ответы не применяются.

## Проверенные места и их смысл

| Место | Прежнее предположение | Решение |
|---|---|---|
| `graph_manager._reach_input` | Единственный источник называется InputNode | Роль input; явный аргумент TrainBegin остаётся для грамматики обучения; добавлена защита от повторного обхода |
| `graph_manager.get_alt_nodes` | Только старые входы и выходы доступны для смены формы | Все зарегистрированные входы взаимозаменяемы; все выходы с ролью output доступны из других выходов. Штатная замена удаляет старые связи; проверки типов работают при повторном подключении. Источник нельзя заменить промежуточным нодом |
| `graph_manager.has_input/is_input_valid` | Только два типа источников | Реестр ролей и проверка живого объекта |
| `graph_creation_catalog`, `cmenu`, `node_palette` | Скрытие источников после первого ввода | Каталог input теперь включает TextInput; потребители получают типы из реестра |
| `cta` | Наличие источника определяется именованным числовым входом, список создания содержит два имени | Видимость использует has_input, список создания — input_types из реестра, включая текст |
| `graph_script_parser` | Корень и передняя группа связей — InputNode | Использует роль источника; специальные TrainBegin/RunModel остаются частью тренировочной грамматики |
| `ui_manager._find_inference_animation_input` | Любой источник — числовой inference | Явно выбирает numeric input; текстовый preview управляется своим controller |
| `run_manager.check_valid` | Выход модели обязательно ClassifierNode | Языковые компоненты явно отклоняются до числового runtime; числовой контракт classifier сохранён |
| `run_manager.export_fully_local_model/export_robot_bundle` | Вход всегда представляет обученную числовую модель | Явная ошибка language_demo_only до чтения модели и запуска экспорта |
| `graph_manager.get_syntax_tree` | Любой Graph сериализуется в числовую грамматику | Явный отказ для языка, отдельный LanguageGraphAdapter |
| `neuron_layer`, `layer_concat`, `softmax` | Только один вектор, ограниченное разветвление | Существующие ноды переиспользованы; сервис адаптирует предел поля и разветвление для языка; штатное оформление сохраняется |
| `netname` | ModelName связывает InputNode и RunModel | Намеренно числовой контракт. У TextInput нет этого config-порта; он не регистрируется как именованная обученная числовая модель |
| `run_m`, `train_begin`, `run_manager._build_train_payload` | TrainBegin/RunModel/TrainInput — числовая тренировочная грамматика | Сохранена; языковой backend имеет отдельный dummy train-интерфейс, реального обучения через эти ноды нет |
| `reshape`, `flatten`, `image_tune`, `augment_transform` | InputNode предоставляет изображение/числовой массив | Намеренно специализированный код; языковые связи с этими типами блокирует адаптер |
| `run_manager` shape validation и ClassifierNode results | Число label_names равно классам датасета | Числовой контракт сохранён. Языковой словарь не передаётся этим обработчикам |
| `simulations/simulation_model_runner`, `simulation_training_bridge`, `simulation_editor` | Выходы classifier — действия агента; input — сенсоры | Намеренно числовые именованные модели, TextInput туда не регистрируется. Не трактовать токены как действия |
| `base_graph` контексты/копирование/сохранение, `connection` один источник | Источник владеет контекстом и не копируется | Сохраняется для TextInput; обход проверяет роль источника |
| Старое восстановление OutputMap в `graph_manager` | Исторические RunModel→TrainStep связи | Миграция старых числовых проектов; не переиспользовать для token_labels |
| `local_runtime/neuralese_local` и generated runtime catalog | Только реализованные числовые handlers | Новые node_defs не объявляют runtime handler. Языковой preview не запускает Python, ONNX, сеть или обучение |
| `tools/jasondocs/godot_static` | Пересечение datatypes означает совместимость | Дополнено ролями language/sequence_capable: GRU/Dropout не предлагаются для языковых нодов |
| `select_nodes.show_nodes/set_node_list` | Пустой список ограничений означает все ноды | Явный пустой список остаётся пустым; полный каталог включается только через show_all_nodes/clear_node_list. Иначе отсутствие допустимых замен открывает весь каталог |
| `train_begin.train_start` | has_input гарантирует числовую модель и подключённый TrainInput | Проверяет числовой источник и тренировочную голову до изменения состояния кнопки/поля. Текстовый граф получает локализованное сообщение о деморежиме; неподключённое обучение не застревает на Stop |

Роль output объявлена и у существующего classifier. Это общая роль для меню, а не обещание одинакового формата данных или доступности числового обучения. TextInput не появляется в именованном селекторе RunModel: у текстового демо нет обученной числовой модели и соответствующего порта ModelName.

Скрытие всех типов входа в левой палитре после появления одного источника — намеренное поведение. Оно распространяется на TextInput; не считать отсутствие его карточки в таком проекте ошибкой регистрации. Правила CTA, ограниченного селектора, замен входов/выходов и отказа обучения покрывает `tests/godot/test_language_menus.tscn`.

## Чеклист следующего типа

Проверять `InputNode`, `ClassifierNode`, `TrainBegin`, `RunModel`, `is_input`, `input_types`, `input_image_small`, `out_labels` по всей кодбазе, включая Python tooling и generated каталоги. Сначала определить смысл каждого сравнения: общая роль или специализированная числовая грамматика. Не заменять все строковые проверки механически.

Новый backend должен объявить словарь/токенизатор и возможности; выдавать исходные token IDs, spans и целые слова для внимания, полные вероятности и ограниченные страницы словаря; сохранять идентичность позиций и проекционный базис; поддерживать отмену и освобождение сессий. Сейчас используется только явно обозначенный deterministic dummy provider. PCA-координаты демонстрационные, не результат обученной модели.


## Контракт типов и размеров

| Данные | Представление | Производитель → потребитель |
| --- | --- | --- |
| `language_text` | UTF-8 текст | TextInput → Tokenizer |
| `language_tokens` | int32 `[T]`, ID и исходные spans | Tokenizer → Embedding |
| `language_vectors` | float32 `[T,D]` | Embedding / AttentionHead / существующие Dense и Concat → следующий векторный этап |
| `language_scores` | float32 `[V]`, вероятности последней позиции, сумма 1 | существующий Softmax → NextToken / TextOutput |

`T` — число токенов; `D` — чисел в одном векторе; `V` — размер словаря. Embedding получает D от модели. AttentionHead выводит D/H из входной размерности и объявленного моделью числа голов; делимость проверяется. Ручной Width отсутствует. Concat сохраняет T и складывает D в порядке слотов. Dense сохраняет T и меняет D на число нейронов. Softmax требует D=V и возвращает распределение для последней позиции. NextToken отображает ограниченное число кандидатов, не выбирает токен заново.

Обычный `layer1d` нельзя считать типом вероятностей или последовательности. `Connection.dtype` использует отдельный языковой контракт при участии языкового компонента. Adapter проверяет также существующие рёбра компонента, чтобы подключение языкового нода не переобозначило несовместимую числовую цепочку. Чисто числовые графы сохраняют старую проверку datatypes; конфигурационные порты остаются в своей грамматике. Статическая документация применяет тот же переход для native Dense/Concat/Softmax.

Формы и типы (`input/output_shape`, `input/output_type`, `input/output_dtype`) передаются в traces. При каждом шаге формы обновляются с overwrite: иначе сохранённое первое T остаётся устаревшим после генерации. ID и spans не заменяются отображаемыми словами; индексы spans относятся к символам исходной строки, не к байтам UTF-8.

Tokenizer и Embedding получают читаемые подписи из исходного текста для byte-fallback токенов. Смежные байты с одним исходным span объединены в одну пиллу символа; переключатель IDs показывает все их номера, выбор любого байта выделяет эту пиллу, щелчок выбирает её первую исходную позицию. Число токенов, dtype, ID, векторы и позиции backend сохраняются. На Embedding каждый исходный токен остаётся отдельной точкой, поэтому байты одного символа могут иметь одинаковую подпись. Без достоверного span UI не пытается угадать символ.

Embedding preview дополнен `points[].z` (третья координата проекции, отдельно от исходного `vector[2]`) и `z_range: [min,max]`. Цвет зависит только от z и диапазона, заданного backend для текущего `basis_id`; UI не нормирует цвета по видимым точкам. Dummy использует постоянные координаты для ID и диапазон [-1,1]. PC1/PC2 остаются осями, PC3 показан цветом и небольшой шкалой; точное значение доступно в подсказке. Выделенная точка сохраняет цвет и получает светлое кольцо. Старые 2D previews без z сохраняют исходный акцент и не показывают шкалу. Реальный backend должен возвращать три компоненты одной проекции и стабильный диапазон вместе с basis_id; настоящая PCA пока не рассчитывается.

Палитра Embedding — ColorBrewer YlGn, последовательная шкала от светло-жёлтого к тёмно-зелёному. Она хранится в `resources/language_models/ylgn.tres`, содержит 256 исходных образцов и отделена от голубого акцента корпуса.

## Визуальные допущения для следующих нодов

- Содержимое задаёт размер; нельзя масштабировать сетку под заранее выбранную карточку. Основной прямоугольник плавно интерполируется к измеренной границе.
- `language_layout.gd` читает Conv2D.tscn: начало содержимого, размер/шаг ячейки, задние отступы, минимальный размер, масштаб и y заголовка, радиус. Это не отдельная таблица произвольных чисел.
- Порты рисуются перед корпусом, который закрывает их внутреннюю часть. Их координаты и линии обновляются при изменении границ.
- Языковая семантика не меняет оформление native Dense/Concat/Softmax. Selection не должен менять base_outline; сплайны используют реальные gradient_color обоих портов. TextInput относится к семейству входов: значения рамки, заголовка, отступов и порта брать из Input2D, а не из синего оформления промежуточных языковых нодов.
- Native BlockComponent запоминает базовую прозрачность в ready и сам анимирует modulate. Для проявления используется прозрачность родителя, чтобы штатная кнопка не оставалась невидимой.
- Проявление в прокручиваемом содержимом учитывать относительно scroll offset. Токены вне первого окна не должны навсегда оставаться прозрачными.
- Все новые названия слитные, включая локализации. NextToken не имеет кнопки «5»; строки растягиваются по внутренней ширине. Количество кандидатов ограничено, полный словарь остаётся постраничным.

- Автоматический языковой пересчёт повторяет принцип Input1D/Input2D: последние текст/граф запускаются после 0,3 секунды покоя. Fingerprint не включает позиции нодов или top_n: перемещение и настройка отображения не запускают генерацию. Controller работает вне экрана; Stop/Reset отменяют ожидающий автозапуск, следующее изменение создаёт новый. Пустой или неподключённый источник только очищает старый просмотр.

- Input2D и TextInput наследуют `input_base.tscn` / `input_base.gd`. Промежуточные языковые ноды не наследуют Input. Языковой controller публикует штатные события визуального inference, не открывая числовой runtime или сеть.
- У TextEdit нативные обводка/скругления рисуются за Control rect через expand margins; clip должен включать эту область. Даже при скрытой прокрутке TextEdit резервирует её ширину, что нужно учитывать при расчёте переносов.
- Static registry должен читать вложенные GDScript и унаследованные свойства порта. Иначе после выделения Input base выход ошибочно считался входом и терял цвет.
