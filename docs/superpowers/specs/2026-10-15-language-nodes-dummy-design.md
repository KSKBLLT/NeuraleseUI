## Ноды и схема

Зарегистрировать девять типов через существующий `graph_types`. Шесть новых по смыслу и три текстовые специализации знакомых нодов. Отдельные type id сохраняют старые числовые графы и их runtime-контракты.

| type id | Назначение и вид | Порты |
|---|---|---|
| `text_input` | Поле текста и запуск; стиль Input1D | `text_out: language_text` |
| `tokenizer` | Токены с читаемыми частями текста; ID по переключателю | `text_in: language_text` → `tokens_out: language_tokens` |
| `embedding` | PCA-поле точек входных токенов; выбранный вектор числами | `tokens_in: language_tokens` → `sequence_out: language_sequence` |
| `attention_head` | Одна голова, одна causal heatmap с подписями слов | `sequence_in: language_sequence` → `sequence_out: language_sequence` |
| `sequence_concat` | Текстовая специализация Склейки, четыре явно упорядоченных слота | `head_0_in` … `head_3_in: language_sequence` → `sequence_out: language_sequence` |
| `sequence_dense` | Текстовый Dense с теми же кружками; применяется к каждой позиции | `sequence_in: language_sequence` → `sequence_out: language_sequence` |
| `token_softmax` | Текстовый Softmax; выбирает позицию и выдаёт распределение словаря | `sequence_in: language_sequence` → `scores_out: language_scores` |
| `token_labels` | Специализация Output Labels: фиксированные top-N строк, поиск | `scores_in: language_scores`, выходов нет |
| `text_output` | Сборка текста, Шаг / Продолжить / Стоп / Сначала | `scores_in: language_scores`, выходов нет |

Названия `server_typename` соответственно: `TextInputNode`, `TokenizerNode`, `EmbeddingNode`, `AttentionHeadNode`, `SequenceConcatNode`, `SequenceDenseNode`, `TokenSoftmaxNode`, `TokenLabelsNode`, `TextOutputNode`.

Эталонный демонстрационный граф: TextInput → Tokenizer → Embedding → четыре параллельные AttentionHead → SequenceConcat → SequenceDense(256) → SequenceDense(8192) → TokenSoftmax; последний выход разветвляется на TokenLabels и TextOutput. Это демонстрация нодов и контрактов, не полная архитектура Llama/9M. Размеры демо: D=256, H=4, d_head=64, V=8192.

В этом этапе головы уже являются отдельными нодами. Автоматическое сворачивание/разворачивание Attention отложено: оно не требуется для проверки нового интерфейса и не должно подменять собой реальную работу нодов.

## Сервис и данные

Один `LanguageModelService` передаёт запросы провайдеру через интерфейс `LanguageBackend`. Сейчас фабрика создаёт только `DummyLanguageBackend`. Ноды не вызывают Python, HTTP, WebSocket, `nn`, ONNX или ML-библиотеки. Визуальные компоненты не генерируют собственные случайные значения.

Все запросы/ответы — JSON-совместимые Dictionary/Array/String/int/float/bool/null. `schema_version=1`. Запрос содержит `request_id`, `session_id`, `graph_revision`, `method`, `params`. Ответ повторяет первые четыре поля идентификации и содержит `provider_id="dummy-v1"`, `is_dummy=true`, `ok`, `result`, `error`. При успехе error=null; при ошибке result=null, error={code,message,node_id}. Сигналы и их полезная нагрузка описаны в плане.

Провайдер принимает snapshot реального графа: nodes=[{id,op,config}], edges=[{from_node,from_port,to_node,to_port}], source_id. ID в контракте — строковые представления стабильных `graph_id`; порядок Concat задаётся портами `head_0_in` … `head_3_in`. Порядок Dictionary и порядок получения ответов не влияют на склейку.

Методы провайдера: capabilities, open_session, tokenize, run_step, inspect, vocabulary_page, train, cancel, close_session. Обучение возвращает только явно помеченные dummy progress/completed события; модель и веса не создаются. Экспорт модели capability=false. Сохранение/загрузка самого графа — настоящее.

`run_step` возвращает next_token_id, generated_ids, decoded_text, finished, stop_reason и nodes — traces по node_id. Каждый trace содержит kind, input_shape, output_shape и preview. Матрицы, точки и значения показываются только из trace. Для Softmax передаётся один полный вектор длиной V для выбранной позиции, не T×V значений; также передаются id/piece для лучших 20 кандидатов и выбранного токена. Это позволяет подписать top-N без 20 отдельных обращений к словарю на каждом шаге. `token_labels` и `text_output` читают один и тот же snapshot; выбор следующего токена выполняется один раз провайдером, а не каждым виджетом.

Токены: id, piece, start, end; диапазоны относятся к Unicode-индексам исходной строки GDScript и проверяются на границах. Повторяющиеся токены различаются occurrence/позицией, ID задаёт словарь. Dummy-токенизация использует фиксированные словарные слова/пунктуацию и обратимый UTF-8 byte fallback. Она явно не называется SentencePiece. Словарь `dummy-v1` имеет 8192 позиции: фиксированные специальные/демо/byte токены и синтетические записи для остальных ID.

## Проверка графа и жизненный цикл

`LanguageGraphAdapter` читает реальные порты, связи и cfg. Он не вызывает числовой `get_syntax_tree()` и не использует `Graph._io()` для передачи языковых пакетов: существующий `propagate()` трактует Dictionary как таблицу выходных портов.

`LanguageGraphValidator` проверяет datatype, наличие входов, цикл, однозначный TextInput, формы T×D, одинаковые позиции/словарь у ветвей, H=4 и d_head=64 в демо, отсутствие повторения/пропуска индекса головы при объединении, порядок склейки, ширину V перед Softmax. Числовые ноды нельзя соединить с новыми языковыми типами без явного подходящего нода.

Генерация управляется контроллером с состояниями idle/running/stopped/completed/error, один запрос run_step одновременно. Продолжить выдаёт не более 32 новых токенов; общий контекст не более 512 токенов. EOS, Stop, ошибка или изменение графа прекращают генерацию. Один кадр UI между шагами позволяет нажать Stop. Смена текста, конфигурации, связей, загрузка проекта и удаление активного нода отменяют старые ответы. Проверять request_id, session_id и graph_revision; закрытие сессии идемпотентно.

В cfg сохраняются текст, пользовательские настройки, head_index/head_count, размеры и порядок слотов, показываемое число кандидатов. Не сохраняются сессии, request_id, большие traces, всё распределение словаря или полный список token labels. Применение trace и чтение словаря не меняют cfg/graph_revision, не вызывают learner.notify_update и не создают undo-действия; иначе ответ сам отменял бы собственную сессию.

## Визуализация

- Материалы, шрифт, порты, рамки и кнопки — существующие Godot-ресурсы. Dense остаётся узкой колонкой кружков; Output Labels сохраняет небольшой зелёный заголовок и компактные полосы, без нового выхода.
- В Embedding показываются входные токены, количество не ограничивается размером выходного словаря. Все точки текущего контекста доступны; подписи разводятся/показываются при наведении, при необходимости поле увеличивается. Выбранный токен имеет стрелку от центра и числовой preview. Dummy-координаты приходят от провайдера; надпись «PCA · демо» исключает утверждение о настоящем PCA. basis_id стабилен внутри сессии и одинаковый токен не прыгает при добавлении текста.
- Heatmap по умолчанию показывает слова; точный режим — токены. Для слова суммируются веса его key-токенов и усредняются строки его query-токенов; исходные causal нули сохраняются в точном режиме. Маска рисуется отдельно от малого веса. Все четыре головы показывают один набор позиций, но разные dummy-веса. В первой строке token-level attention единственный доступный вес равен 1 у каждой головы.
- По умолчанию heatmap рисует окно до 16 позиций. Переход по окнам/Expand позволяет inspect других позиций до 512, не обрезая исполняемый контекст. В Token Labels показывается одна позиция — та же, что используется для генерации.
- Token Labels создаёт ровно N строк: N∈{5,10,20}, default 5. «Остальные» содержит массу всех V−N токенов; top-N не меняет выбор токена. Полный словарь — отдельный диалог с поиском и страницами по 50 строк, а не тысячи Controls. Вероятности нормированы по всему V. Выбранный ID сохраняется при сортировке и поиске.
- Состояния empty/loading/error/cancelled/demo видимы. Цифры и карты появляются после ответа сервиса. Dummy-результаты подписаны «Демо-данные»; сообщение об успешном настоящем обучении не показывается.

## Приёмка

Собрать граф из палитры, ввести текст, увидеть токены, PCA-точки, четыре разные causal карты, корректные формы и общий выбранный выход. Изменить текст/связи, остановить и сбросить генерацию без запоздалых обновлений. Сохранить и открыть граф. Найти токен вне top-5 при V=8192/65536 без создания полного списка Controls. Старые числовые ноды и тесты сохраняют поведение.

Рендеры выполняются настоящим Godot, не ImageGen. Проверяются 1280×720 и 1440×900, zoom 0.75/1/1.5, RU/EN/KZ, короткий и длинный контекст. Новые тесты добавляются в существующий marker-based runner. Настоящее ML-качество этот этап не проверяет.
