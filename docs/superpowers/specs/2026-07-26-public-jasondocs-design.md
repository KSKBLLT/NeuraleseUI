# Публичная документация Neuralese из JasonDocs

## Цель

Создать на `neuralese.asia/docs` понятную русскоязычную документацию по
нодам Neuralese для школьников и учителей. Первая версия публикует пять
базовых нодов и используется как пилот для проверки структуры, языка и
визуального представления до расширения каталога.

Работа сфокусирована на стабилизации и полировке. Она не меняет поведение
нодов, формат графа, YAML DSL, обучение, API или интерфейс редактора.

## Объем первой версии

В пилот входят пять нодов, образующих понятную цепочку классификации:

1. `input_1d` — Ввод1D;
2. `layer` — Полносвязный слой;
3. `neuron` — Активация;
4. `softmax` — Софтмакс;
5. `classifier` — Метки выхода.

Публичная страница пока работает только на русском языке. Существующие
английские и казахские тексты не удаляются и не переписываются в рамках
этой задачи.

## Единый источник правды

`neuralese-builder/JasonDocs` остается единственным редактируемым источником
описаний и изображений нодов.

Для каждого нода используются:

- `JasonDocs/<node_id>/node.json`;
- русские поля внутри секции `docs`;
- `JasonDocs/<node_id>/icon.png`;
- технические сведения из секции `generated`.

Секция `generated` не редактируется вручную. Она продолжает принадлежать
существующему статическому анализатору JasonDocs. Публичный сайт не содержит
второй копии описаний и не вводит отдельное сопоставление типов нодов с
текстом.

## Правила авторского текста

Русский текст пишется вручную на основе реального поведения сцены, GDScript
и сгенерированных портов. Формулировка считается готовой только тогда, когда
ее может понять школьник без знания внутренних названий Neuralese и учитель
может использовать ее для объяснения темы.

Каждое описание должно отвечать на следующие вопросы:

1. Что это за нод?
2. Какие данные приходят в него?
3. Что он делает с этими данными?
4. Куда передается результат?
5. Когда этот нод нужен в модели?
6. Что изменяет каждая видимая настройка?
7. Как выглядит один корректный пример подключения?
8. Какую типичную ошибку важно не допустить?

Текст не обязан слепо повторять одну конструкцию. Например, Активация
подключается как настройка слоя, а Ввод1D сам создает начальный поток
признаков. Описание должно отражать фактическую роль конкретного нода.

Запрещены необъясненные фразы вида:

- «принимает данные типа `layer1d`»;
- «передает через `layer_in`»;
- «хранит настроенные значения»;
- «используется совместимыми следующими узлами».

Если внутреннее имя необходимо показать, сначала дается понятное название,
а техническое имя указывается вторично.

## Использование существующей схемы

Новые поля в JasonDocs не добавляются. Содержание распределяется по уже
существующим полям:

- `docs.title.ru` — понятное название;
- `docs.summary.ru` — одно короткое объяснение;
- `docs.operation.ru` — путь данных, назначение и ситуация применения;
- `docs.compact.body.ru` — краткая версия для небольших поверхностей;
- `docs.ports.*.label.ru` — человеческое название порта;
- `docs.ports.*.description.ru` — что подключается и зачем;
- `docs.settings.*.label.ru` — понятное название настройки;
- `docs.settings.*.description.ru` — практический эффект изменения;
- `docs.examples` — примеры цепочек и практические предупреждения, когда
  это полезно.

Поля `examples` уже поддерживаются текущей схемой и генератором. Их
использование является наполнением существующего формата, а не расширением
DSL.

## Генерация данных для сайта

Сборка публичной документации использует существующий инструментарий
`tools.jasondocs`.

Поток данных:

```text
JasonDocs/<node_id>/node.json + icon.png
                    |
                    v
      tools.jasondocs validate/runtime
                    |
                    v
        статический catalog.json + icons
                    |
                    v
      React/Vite страница neuralese.asia/docs
```

Во время сборки лендинга:

1. checkout получает актуальный `neuralese-builder`;
2. запускается строгая проверка JasonDocs;
3. существующий runtime-генератор создает JSON-каталог;
4. иконки выбранных нодов копируются из JasonDocs;
5. отдельная проверка требует наличие всех пяти документов и изображений;
6. Vite собирает статическую страницу.

Для чтения приватного builder-репозитория CI использует отдельный
fine-grained GitHub token с доступом только на чтение Contents. Токен хранится
в GitHub Actions Secrets и никогда не попадает в браузерный bundle.

Первая версия не добавляет runtime-запросы к GitHub или Neuralese API.
Документация продолжает работать при временной недоступности backend.

## Публикуемый набор

Описания и изображения всегда берутся динамически из сгенерированного
каталога. Небольшой presentation-конфиг лендинга содержит только порядок
первых пяти `node_id`. Он не содержит текстов, портов, настроек или путей к
конкретным файлам.

Если указанный нод отсутствует, не прошел валидацию или не имеет иконки,
production build завершается ошибкой. Сайт не должен тихо публиковать
неполную документацию.

## Маршрут и компоненты

Лендинг остается приложением React 19 + Vite. Новый тяжелый роутер не нужен:
корневой компонент выбирает существующую главную страницу или
документацию по `window.location.pathname`.

Поддерживаются:

- `/` — существующий лендинг без визуальных и поведенческих изменений;
- `/docs` и `/docs/` — единая страница документации с переключением между
  опубликованными нодами без дополнительных маршрутов.

Nginx уже отдает SPA для `/docs`; прямое открытие и обновление этой страницы
необходимо проверить отдельно.

## Визуальная структура

Страница документации переиспользует визуальный язык действующего лендинга:

- логотип Neuralese;
- существующие Navbar и Footer;
- `Instrument Sans` для интерфейса;
- `Fraunces` для крупных заголовков;
- светлый фон, темный текст и синий акцент;
- существующие CSS-переменные, границы и кнопки.

Документация является рабочей поверхностью, а не маркетинговой страницей.
Она не получает отдельный hero, декоративные секции или тяжелую анимацию.

### Desktop

- компактная левая навигация со списком пяти нодов и их иконками;
- основная статья с ограниченной читаемой шириной;
- в шапке статьи — настоящая иконка, название и краткое описание;
- далее — «Как проходит информация», «Подключения», «Настройки»,
  «Примеры и важные замечания», если эти данные доступны.

### Mobile

- навигация превращается в горизонтальный прокручиваемый список;
- статья занимает полную доступную ширину;
- схема «вход → действие → выход» становится вертикальной;
- текст и изображения не перекрываются и не требуют горизонтального
  скролла страницы.

## Представление потока данных

Путь через нод показывается в трех смысловых частях:

1. что подключается слева или откуда появляются данные;
2. что нод делает;
3. какой результат выходит справа и куда его можно подключить.

Эти части строятся из авторского `operation` и описаний реальных портов.
Сайт не пытается угадывать семантику по внутренним именам и не генерирует
объяснение эвристиками.

## Редакторская проверка

После подготовки первых пяти нодов:

1. тексты проверяются на соответствие сценам и скриптам;
2. локальная страница передается владельцу задачи и Арысу;
3. замечания к формулировкам вносятся в JasonDocs;
4. генерация запускается повторно;
5. только одобренная версия готовится к PR и деплою.

## Ошибки и защитные проверки

- Некорректный JSON: сборка завершается ошибкой с путем к документу.
- Устаревшая секция `generated`: `jasondocs validate` завершает сборку
  ошибкой.
- Нет русского текста обязательного поля: пилотная проверка завершает сборку
  ошибкой.
- Нет иконки: сборка завершается ошибкой.
- Нод не входит в опубликованный список: он не появляется в навигации и не
  открывается по публичному маршруту.
- Недоступен GitHub во время CI: предыдущая production-версия остается
  активной, новый неполный deploy не выполняется.

## Проверки

### Builder

- `python -m tools.jasondocs sync --dry-run`;
- `python -m tools.jasondocs runtime`;
- `python -m tools.jasondocs validate`;
- проверка, что секции `generated` пяти файлов не изменились;
- существующие Python- и Godot-тесты каталога нодов.

### Landing

- TypeScript-проверка;
- production build;
- автоматическая проверка пяти документов и пяти иконок;
- `/` визуально и функционально не изменился;
- `/docs` открывается напрямую;
- `/docs` сохраняет работоспособность после обновления страницы;
- навигация и статьи проверены на desktop и mobile;
- отсутствуют ошибки консоли, горизонтальное переполнение и битые изображения.

## Не входит в задачу

- изменение поведения нодов;
- изменение YAML DSL или встроенных уроков;
- редизайн главной страницы;
- поиск, аккаунты, комментарии или аналитика в документации;
- автоматический перевод;
- публикация всех 21 нодов до ручной проверки;
- runtime API для документации;
- новая схема JasonDocs;
- отображение документации внутри Godot.

## Критерии готовности

Задача считается готовой, когда:

1. пять русских документов понятны школьнику и полезны учителю;
2. каждый факт соответствует реальному ноду;
3. тексты и изображения берутся только из JasonDocs;
4. главная страница лендинга не изменилась;
5. `/docs` и пять вложенных страниц работают на desktop и mobile;
6. все проверки проходят;
7. владелец задачи и Арыс одобрили формулировки до production-деплоя.
